# 시스템 설계 면접 준비 10선

"URL 단축기를 설계하세요", "Instagram 피드를 설계하세요" 같은 시스템 설계 면접을
대비하기 위한 핵심 10편. 외우는 게 아니라 원리를 이해하는 순서로 정렬했습니다.

---

## 설계의 전제 — 수평 확장과 트레이드오프 (1–3편)

시스템 설계의 모든 결정은 이 3가지 원칙 위에 있습니다.

1. [Infrastructure Design Principles](../DevOps/Principles/Infrastructure_Design_Principles.md)
   — 확장성(Scalability), 가용성(Availability), 유지보수성. 면접관이 기대하는 언어.

2. [Infrastructure High Availability](../DevOps/Principles/Infrastructure_High_Availability.md)
   — Active-Active vs Active-Passive. SPOF 제거 전략.

3. [Infrastructure Capacity Planning](../DevOps/Principles/Infrastructure_Capacity_Planning.md)
   — QPS 계산, 스토리지 추정. 면접 첫 5분을 지배하는 기술.

---

## 데이터 레이어 설계 (4–6편)

"어떤 DB를 쓰고 어떻게 확장하나"에 답하는 3편.

4. [Aurora DB Cluster](../Cloud/AWS/Database/Aurora_DB_Cluster.md)
   — 읽기 확장, 자동 장애조치. "읽기 트래픽이 몰리면?"에 대한 답.

5. [ElastiCache](../Cloud/AWS/Database/ElastiCache.md)
   — 캐시 레이어 설계. Cache-Aside vs Write-Through 전략.

6. [DynamoDB](../Cloud/AWS/Database/DynamoDB.md)
   — NoSQL 선택 기준. 파티션 키 설계와 핫 파티션 회피.

---

대용량 처리의 핵심 — 동기를 끊어내는 방법.

7. [SNS SQS Lambda 통합 메시지 파이프라인](../Cloud/AWS/Application_Integration/SNS_SQS_Lambda_통합_메시지_파이프라인.md)

8. [MSK (Managed Kafka)](../Cloud/AWS/Application_Integration/MSK.md)
   — Kafka 기반 스트리밍. SQS와 선택 기준 비교.

## 면접 시나리오 예시

### URL 단축기 설계
- 쓰기: API Gateway → Lambda → DynamoDB (파티션 키: short_code)
- 읽기: CloudFront → Lambda → ElastiCache → DynamoDB
- 추정: 하루 100M 요청 → 1,000 QPS → t3.medium 2대

### 알림 시스템 설계
- 이벤트 발행: SNS Topic
- 채널별 처리: SQS + Lambda (이메일/푸시/SMS 분기)
- 재시도: DLQ + 지수 백오프

### 피드 시스템 설계
- 작성 시: SNS → SQS → Lambda (팔로워 피드 Fan-out Write)
- 읽기 시: ElastiCache (Redis Sorted Set으로 최신 100건 캐싱)
- 대용량 팔로워: 읽기 시점 Fan-out (인플루언서 계정)
