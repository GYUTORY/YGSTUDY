# 인덱스와 쿼리 성능 허브

## 이 주제를 언제 찾게 되는가

- 쿼리가 갑자기 느려졌는데 EXPLAIN 결과를 어떻게 읽어야 할지 모를 때
- 인덱스를 추가했는데 옵티마이저가 사용하지 않거나 잘못된 인덱스를 선택할 때
- 대용량 테이블에서 페이지네이션이 뒤로 갈수록 급격히 느려질 때
- Slow Query Log를 분석해서 튜닝 우선순위를 정해야 할 때
- DB 통계 정보가 오래되어 실행 계획이 엉뚱하게 나올 때

## 읽는 순서

1. **RDBMS 인덱스** — 여기까지 읽으면 B-Tree 구조와 인덱스 설계의 기본 판단 기준이 생긴다
2. **데이터베이스 옵티마이저** — 옵티마이저가 비용을 어떻게 추정하고 플랜을 선택하는지 원리를 이해한다
3. **쿼리 옵티마이저 (RDBMS)** — EXPLAIN 결과를 실제로 읽고 느린 쿼리를 진단하는 방법을 익힌다
4. **데이터베이스 성능 튜닝** — Slow Query Log부터 시작해 체계적 튜닝 절차를 적용한다
5. **API 페이지네이션 패턴** — 대용량 목록 API에서 Keyset 방식으로 전환하는 시점과 방법을 결정한다

## 아직 없는 것

- PostgreSQL 전용 인덱스 타입(GIN, GiST, BRIN) 비교 문서
- 파티셔닝 전략 전용 심화 문서 (Range·List·Hash 비교)
- 복합 인덱스 컬럼 순서 결정 기준 전용 문서
- 쿼리 힌트(USE INDEX, FORCE INDEX) 실전 적용 가이드
- 통계 정보 수동 갱신(ANALYZE) 타이밍 전략
