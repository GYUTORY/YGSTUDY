# JavaScript Proxy (객체 동작 가로채기)

## 배경

JavaScript Proxy는 객체의 기본 동작을 가로채서 사용자가 원하는 대로 고칠 수 있게 해주는 기능이다.

가로챈다는 건 우체부가 편지를 전달하기 전에 내용을 확인하고 고칠 수 있는 것과 같다. Proxy도 객체에 접근하기 전에 그 동작을 확인하고 바꾼다.

### Proxy의 기본 구조
```javascript
const proxy = new Proxy(target, handler);
```

- **target**: 프록시로 감쌀 원본 객체
- **handler**: 동작을 가로채는 규칙들이 담긴 객체

### Proxy의 주요 용도
- 속성 접근 제어 및 검증
- 로깅 및 디버깅
- 기본값 제공
- 데이터 변환
- 보안 강화

## 핵심

### Proxy 기본 사용법

```javascript
// 1. 원본 객체
const originalUser = {
    name: '김철수',
    age: 25
};

// 2. 가로채기 규칙 (handler)
const handler = {
    // 속성에 접근할 때 실행되는 함수
    get: function(target, propertyName) {
        console.log(`${propertyName} 속성에 접근했습니다!`);
        return target[propertyName];
    },
    
    // 속성 값을 설정할 때 실행되는 함수
    set: function(target, propertyName, newValue) {
        console.log(`${propertyName} 속성을 ${newValue}로 변경합니다!`);
        target[propertyName] = newValue;
        return true; // 성공적으로 설정됨을 알림
    }
};

// 3. Proxy 객체 생성
const userProxy = new Proxy(originalUser, handler);

// 4. 사용해보기
console.log(userProxy.name); 
// 출력: "name 속성에 접근했습니다!"
// 출력: "김철수"

userProxy.age = 30;
// 출력: "age 속성을 30으로 변경합니다!"
```

### 주요 트랩(Trap) 메서드들

#### 1. get() - 속성 접근 가로채기

속성에 접근할 때 (`obj.property`, `obj['property']`) 실행된다.

```javascript
const handler = {
    get: function(target, propertyName, receiver) {
        // target: 원본 객체
        // propertyName: 접근하려는 속성 이름
        // receiver: Proxy 객체 자체
        
        console.log(`${propertyName} 속성을 찾고 있습니다...`);
        
        // 속성이 존재하는지 확인
        if (propertyName in target) {
            return target[propertyName];
        } else {
            return `${propertyName} 속성은 존재하지 않습니다.`;
        }
    }
};

const user = new Proxy({
    name: '김철수',
    age: 25
}, handler);

console.log(user.name);     // "김철수"
console.log(user.email);    // "email 속성은 존재하지 않습니다."
```

없는 속성에 **아무 값이나 돌려주는 `get` 트랩**은 이 객체를 언어의 다른 기능과 함께 쓸 수 없게 만든다. 자바스크립트는 객체를 다룰 때 우리가 모르는 이름들을 조용히 조회하기 때문이다.

```javascript
`${user}`;
// TypeError: string "Symbol(Symbol.toPrimitive) 속성은 존재하지 않습니다." is not a function

[...user];
// TypeError: user is not iterable
```

문자열 변환은 `Symbol.toPrimitive` 를 찾고, 스프레드는 `Symbol.iterator` 를 찾는다. 원래는 `undefined` 가 나와서 "없구나" 하고 다음 경로로 넘어가는데, 트랩이 문자열을 돌려주니 **있는 줄 알고 호출한다.** 콘솔 출력, 비교, 반복문처럼 평범한 자리에서 갑자기 터진다.

`propertyName` 이 문자열이라는 가정도 위험하다. **심볼도 그대로 들어온다.**

```javascript
const h = { has(t, p) { if (p.startsWith('_')) return false; return p in t; } };
Symbol.iterator in new Proxy({}, h);
// TypeError: p.startsWith is not a function
```

문서의 `has` 트랩과 `deleteProperty` 트랩이 둘 다 `propertyName.startsWith('_')` 를 쓴다. 심볼 키가 한 번이라도 조회되면 그 자리에서 예외다.

트랩을 쓸 때의 기본 자세는 **모르는 키는 원래 동작으로 넘긴다**이다. `Reflect` 가 그 "원래 동작"을 그대로 제공한다.

```javascript
get(target, prop, receiver) {
  if (typeof prop !== 'string' || !(prop in target)) {
    return Reflect.get(target, prop, receiver);   // 없으면 undefined 가 나온다
  }
  ...
}
```

#### 2. set() - 속성 설정 가로채기

속성 값을 설정할 때 (`obj.property = value`) 실행된다.

```javascript
const handler = {
    set: function(target, propertyName, newValue) {
        console.log(`${propertyName} 속성을 ${newValue}로 설정하려고 합니다.`);
        
        // 나이에 대한 유효성 검사
        if (propertyName === 'age') {
            if (typeof newValue !== 'number') {
                throw new Error('나이는 숫자여야 합니다!');
            }
            if (newValue < 0 || newValue > 150) {
                throw new Error('나이는 0~150 사이여야 합니다!');
            }
        }
        
        // 이름에 대한 유효성 검사
        if (propertyName === 'name') {
            if (typeof newValue !== 'string') {
                throw new Error('이름은 문자열이어야 합니다!');
            }
            if (newValue.length < 2) {
                throw new Error('이름은 2글자 이상이어야 합니다!');
            }
        }
        
        // 모든 검사를 통과하면 실제로 설정
        target[propertyName] = newValue;
        console.log(`${propertyName} 속성이 성공적으로 설정되었습니다.`);
        return true;
    }
};

const user = new Proxy({}, handler);

user.name = '김철수';  // 성공
user.age = 25;        // 성공

// user.age = '스물다섯';  // Error: 나이는 숫자여야 합니다!
// user.age = -5;         // Error: 나이는 0~150 사이여야 합니다!
// user.name = '김';      // Error: 이름은 2글자 이상이어야 합니다!
```

#### 3. has() - 속성 존재 확인 가로채기

`in` 연산자를 사용할 때 (`'property' in obj`) 실행된다.

```javascript
const handler = {
    has: function(target, propertyName) {
        // 언더스코어(_)로 시작하는 속성은 private으로 처리
        if (propertyName.startsWith('_')) {
            console.log(`${propertyName}은 private 속성입니다.`);
            return false; // 존재하지 않는 것처럼 처리
        }
        
        return propertyName in target;
    }
};

const user = new Proxy({
    name: '김철수',
    age: 25,
    _password: 'secret123',
    _email: 'test@example.com'
}, handler);

console.log('name' in user);      // true
console.log('age' in user);       // true
console.log('_password' in user); // false (private 속성)
console.log('_email' in user);    // false (private 속성)
```

#### 4. deleteProperty() - 속성 삭제 가로채기

`delete` 연산자를 사용할 때 (`delete obj.property`) 실행된다.

```javascript
const handler = {
    deleteProperty: function(target, propertyName) {
        console.log(`${propertyName} 속성을 삭제하려고 합니다.`);
        
        // 중요한 속성은 삭제 방지
        if (propertyName === 'id' || propertyName === 'name') {
            throw new Error(`${propertyName}은 삭제할 수 없는 중요 속성입니다!`);
        }
        
        // private 속성도 삭제 방지
        if (propertyName.startsWith('_')) {
            throw new Error('private 속성은 삭제할 수 없습니다!');
        }
        
        delete target[propertyName];
        console.log(`${propertyName} 속성이 삭제되었습니다.`);
        return true;
    }
};

const user = new Proxy({
    id: 1,
    name: '김철수',
    age: 25,
    _password: 'secret123'
}, handler);

delete user.age;        // 성공
// delete user.name;    // Error: name은 삭제할 수 없는 중요 속성입니다!
// delete user._password; // Error: private 속성은 삭제할 수 없습니다!
```

## 예시

### 1. 기본값 제공 Proxy

```javascript
const defaultHandler = {
    get: function(target, propertyName) {
        if (propertyName in target) {
            return target[propertyName];
        } else {
            // 기본값 반환
            const defaults = {
                name: 'Unknown',
                age: 0,
                email: 'no-email@example.com'
            };
            // ?? 를 쓴다. || 로 쓰면 age 의 기본값 0 이 falsy 라 걸러져
            //  '기본값 없음' 이 나온다 — 기본값으로 0 이나 빈 문자열을 두는 순간 터진다.
            return defaults[propertyName] ?? '기본값 없음';
        }
    }
};

const user = new Proxy({}, defaultHandler);

console.log(user.name);   // "Unknown"
console.log(user.age);    // 0
console.log(user.email);  // "no-email@example.com"
console.log(user.phone);  // "기본값 없음"
```

`user.age` 는 `0` 이 아니라 `'기본값 없음'` 이다.

```javascript
return defaults[propertyName] || '기본값 없음';
//     defaults.age 는 0 → falsy → 오른쪽으로 넘어간다
```

기본값 표를 만들어 놓고 그중 falsy 인 항목만 표에서 빠진 것처럼 취급하게 된다. `0`, `''`, `false` 는 기본값으로 자주 쓰이는 값이라 이 실수의 사정거리가 넓다. 게다가 숫자를 기대하던 자리에 문자열이 들어가서 `user.age + 1` 이 `'기본값 없음1'` 이 된다.

`||` 대신 `??` 를 쓰거나, 애초에 키가 있는지로 판단한다.

```javascript
return propertyName in defaults ? defaults[propertyName] : '기본값 없음';
```

### 2. 로깅 Proxy

```javascript
const loggingHandler = {
    get: function(target, propertyName) {
        console.log(`[GET] ${propertyName} 속성에 접근`);
        return target[propertyName];
    },
    
    set: function(target, propertyName, value) {
        console.log(`[SET] ${propertyName} = ${value}`);
        target[propertyName] = value;
        return true;
    },
    
    deleteProperty: function(target, propertyName) {
        console.log(`[DELETE] ${propertyName} 속성 삭제`);
        delete target[propertyName];
        return true;
    }
};

const config = new Proxy({
    apiUrl: 'https://api.example.com',
    timeout: 5000
}, loggingHandler);

config.apiUrl = 'https://new-api.example.com';
// [SET] apiUrl = https://new-api.example.com

console.log(config.timeout);
// [GET] timeout 속성에 접근
// 5000

delete config.timeout;
// [DELETE] timeout 속성 삭제
```

### 3. 유효성 검사 Proxy

```javascript
const validationHandler = {
    set: function(target, propertyName, value) {
        const validators = {
            email: (email) => {
                const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
                return emailRegex.test(email);
            },
            age: (age) => {
                return typeof age === 'number' && age >= 0 && age <= 150;
            },
            phone: (phone) => {
                const phoneRegex = /^[0-9-+()\s]+$/;
                return phoneRegex.test(phone);
            }
        };
        
        if (validators[propertyName]) {
            if (!validators[propertyName](value)) {
                throw new Error(`${propertyName}의 값이 유효하지 않습니다: ${value}`);
            }
        }
        
        target[propertyName] = value;
        return true;
    }
};

const user = new Proxy({}, validationHandler);

user.email = 'valid@example.com';  // 성공
user.age = 25;                     // 성공
user.phone = '010-1234-5678';      // 성공

// user.email = 'invalid-email';   // Error: email의 값이 유효하지 않습니다
// user.age = -5;                  // Error: age의 값이 유효하지 않습니다
```

### 4. 읽기 전용 Proxy

```javascript
const readOnlyHandler = {
    set: function(target, propertyName, value) {
        throw new Error(`${propertyName} 속성은 읽기 전용입니다!`);
    },
    
    deleteProperty: function(target, propertyName) {
        throw new Error(`${propertyName} 속성은 삭제할 수 없습니다!`);
    }
};

const constants = new Proxy({
    PI: 3.14159,
    GRAVITY: 9.8,
    MAX_SIZE: 1000
}, readOnlyHandler);

console.log(constants.PI);  // 3.14159

// constants.PI = 3.14;     // Error: PI 속성은 읽기 전용입니다!
// delete constants.PI;     // Error: PI 속성은 삭제할 수 없습니다!
```

`set` 과 `deleteProperty` 두 개만 막으면 읽기 전용이 되지 않는다. **속성을 바꾸는 경로가 그 둘만이 아니다.**

```javascript
Object.defineProperty(constants, 'PI', { value: 3 });
constants.PI;   // 3   ← 막히지 않았다
```

`defineProperty` 트랩을 정의하지 않았으니 그대로 원본에 전달된다. `Object.assign` 은 `set` 을 거치므로 막히지만 `Object.defineProperties`, `Object.setPrototypeOf` 같은 것들은 각자의 트랩이 필요하다.

프록시로 "무언가를 금지"할 때는 **막아야 할 트랩을 빠짐없이 나열**해야 하고, 그건 13개짜리 표를 보며 하나씩 판단해야 하는 일이다. 진짜로 얼리는 게 목적이면 프록시보다 `Object.freeze(target)` 가 확실하다. 언어가 모든 경로를 막아 준다.

프록시에는 반대 방향의 제약도 있다. **원본이 `writable: false, configurable: false` 인 속성은 트랩이 거짓말을 할 수 없다.**

```javascript
const t = {};
Object.defineProperty(t, 'fixed', { value: 1, writable: false, configurable: false });
const p = new Proxy(t, { get() { return '다른 값'; } });

p.fixed;
// TypeError: 'get' on proxy: property 'fixed' is a read-only and non-configurable
// data property on the proxy target but the proxy did not return its actual value
```

프록시가 지켜야 하는 불변식이 명세에 정해져 있어서, 어길 경우 조용히 무시되는 게 아니라 예외가 난다. 남이 준 객체를 프록시로 감쌀 때 그 객체에 얼려진 속성이 있으면 여기서 걸린다.

### 5. 배열 인덱스 검증 Proxy

```javascript
const arrayHandler = {
    set: function(target, propertyName, value) {
        // 배열 인덱스 검증
        const index = parseInt(propertyName);
        if (!isNaN(index)) {
            if (index < 0) {
                throw new Error('배열 인덱스는 0 이상이어야 합니다!');
            }
            if (index > target.length) {
                throw new Error('배열의 길이를 초과하는 인덱스입니다!');
            }
        }
        
        target[propertyName] = value;
        return true;
    }
};

const numbers = new Proxy([1, 2, 3], arrayHandler);

numbers[1] = 10;     // 성공
numbers[0] = 5;      // 성공

// numbers[-1] = 0;   // Error: 배열 인덱스는 0 이상이어야 합니다!
// numbers[10] = 100; // Error: 배열의 길이를 초과하는 인덱스입니다!
```

## 운영 팁

### Proxy 사용 시 주의사항

#### 1. 성능 고려사항
```javascript
// Proxy는 일반 객체보다 성능이 느림
const normalObject = { name: 'test' };
const proxyObject = new Proxy({ name: 'test' }, {});

// 대량의 속성 접근 시 성능 차이 발생
for (let i = 0; i < 1000000; i++) {
    normalObject.name;  // 빠름
    proxyObject.name;   // 느림
}
```

얼마나 느린지는 재 봐야 안다. 같은 환경에서 500만 번 속성을 읽은 결과다.

```
일반 객체            3ms
빈 handler 프록시    41ms
get 트랩 프록시      93ms
```

트랩을 하나도 정의하지 않은 프록시조차 그냥 객체보다 눈에 띄게 느리다. 프록시를 거치는 순간 자바스크립트 엔진의 인라인 캐시·히든 클래스 최적화가 통하지 않기 때문이다. 다만 절대값을 보면 500만 번에 밀리초 단위라, **대부분의 코드에서는 문제가 되지 않는다.** 문제가 되는 자리는 정해져 있다 — 렌더 루프, 대량 데이터 순회, 프레임마다 도는 계산처럼 **같은 속성을 수십만 번 읽는 곳**이다. 반응형 상태 라이브러리들이 프록시로 감싸는 대상을 최소화하려 애쓰는 이유다.

성능보다 먼저 걸리는 것이 하나 더 있다. **프록시는 원본과 다른 객체다.**

```javascript
const target = {};
const p = new Proxy(target, {});

p === target;                       // false
new Map([[target, 'v']]).get(p);    // undefined
new WeakSet([target]).has(p);       // false
```

`Map`·`Set`·`WeakMap` 은 참조 동일성으로 키를 찾으므로, 어떤 코드가 원본을 키로 넣고 다른 코드가 프록시로 조회하면 못 찾는다. 캐시·방문 표시·순환 참조 감지처럼 **"이 객체를 본 적 있는가"를 판단하는 코드가 전부 이 함정에 걸린다.** 프록시로 감싼 객체를 그런 자료구조와 섞어 쓰려면 어느 쪽을 키로 쓸지 한 곳에서 정해 놓아야 한다.

`instanceof` 는 프록시가 `getPrototypeOf` 를 위임하므로 대체로 통과하지만, 그 트랩을 직접 정의하면 그것도 달라진다. **프록시를 도입하면 "이 값이 무엇인가"를 판정하는 모든 코드가 검토 대상이 된다** — 이게 성능보다 큰 대가다.

#### 2. 무한 루프 방지
```javascript
const handler = {
    get: function(target, propertyName) {
        // 무한 루프 방지: target[propertyName] 대신 Reflect 사용
        return Reflect.get(target, propertyName);
    }
};
```

#### 3. 메서드 호출 가로채기
```javascript
const methodHandler = {
    get: function(target, propertyName) {
        const value = target[propertyName];
        
        // 함수인 경우에만 가로채기
        if (typeof value === 'function') {
            return function(...args) {
                console.log(`${propertyName} 메서드가 호출되었습니다.`);
                return value.apply(target, args);
            };
        }
        
        return value;
    }
};

const calculator = new Proxy({
    add: (a, b) => a + b,
    multiply: (a, b) => a * b
}, methodHandler);

calculator.add(5, 3);      // "add 메서드가 호출되었습니다." 출력 후 8 반환
calculator.multiply(4, 2); // "multiply 메서드가 호출되었습니다." 출력 후 8 반환
```

`value.apply(target, args)` 의 `target` 이 문제다. 메서드 안의 `this` 가 **프록시가 아니라 원본 객체**가 되어, 그 메서드가 하는 속성 변경이 트랩을 전부 빠져나간다.

```javascript
const logged = new Proxy({ count: 0, inc() { this.count++; } }, {
  get(t, p) { const v = t[p]; return typeof v === 'function' ? (...a) => v.apply(t, a) : v; },
  set(t, p, v) { console.log('[SET]', p, '=', v); t[p] = v; return true; }
});

logged.inc();
// [SET] 이 찍히지 않는다
logged.count;   // 1 — 값은 바뀌었는데 로그에는 안 남았다
```

밖에서 `logged.count = 1` 로 바꾸면 로그가 남고, 메서드를 통해 바꾸면 안 남는다. 감시 도구로서는 반쪽이고, 반응형 시스템이라면 화면이 갱신되지 않는다. 문서 아래쪽 `createReactive` 도 같은 구조라, 데이터 객체에 메서드를 하나 붙이는 순간 그 경로의 변경은 UI 에 반영되지 않는다.

`receiver` 를 쓰면 된다. `get` 트랩의 세 번째 인자가 프록시 자신이다.

```javascript
get(target, prop, receiver) {
  const v = Reflect.get(target, prop, receiver);
  if (typeof v !== 'function') return v;
  return (...args) => v.apply(receiver, args);   // ← this 를 프록시로
}
```

`Reflect` 를 쓰라는 조언이 흔히 "무한 루프 방지"로 설명되는데, 실제로 중요한 건 이 `receiver` 전달이다. `target[prop]` 은 receiver 를 잃어버려서 getter 와 메서드의 `this` 가 원본으로 떨어진다.

아래 `createCachedAPI` 에는 더 넓은 문제가 있다. `get` 트랩이 **어떤 이름으로 물어봐도 함수를 돌려준다.** 그래서 이 객체는 자기도 모르게 thenable 이 된다.

```javascript
typeof api.then;   // 'function'

await api;         // 영원히 끝나지 않는다
```

`await` 는 `then` 이 함수면 프로미스로 간주하고 `then(resolve, reject)` 를 부른다. 여기서 만들어진 `then` 은 원본에 없는 메서드를 부르려다 `undefined` 를 돌려주고 끝나므로, `resolve` 가 영영 호출되지 않는다. 에러도 없이 그 자리에서 멈춘다.

이 API 객체를 프로미스와 함께 쓰는 순간(`Promise.all` 에 섞거나 `async` 함수에서 반환하기만 해도) 걸린다. 트랩이 아무 이름에나 응답하게 만들면 안 되는 이유가 이것이다.

### Proxy와 Reflect 함께 사용하기

```javascript
const handler = {
    get: function(target, propertyName, receiver) {
        console.log(`${propertyName} 속성에 접근`);
        return Reflect.get(target, propertyName, receiver);
    },
    
    set: function(target, propertyName, value, receiver) {
        console.log(`${propertyName} 속성을 ${value}로 설정`);
        return Reflect.set(target, propertyName, value, receiver);
    }
};
```

## 참고

### Proxy의 모든 트랩 메서드

| 트랩 | 설명 | 트리거 |
|------|------|--------|
| `get` | 속성 읽기 | `obj.prop`, `obj['prop']` |
| `set` | 속성 쓰기 | `obj.prop = value` |
| `has` | 속성 존재 확인 | `'prop' in obj` |
| `deleteProperty` | 속성 삭제 | `delete obj.prop` |
| `ownKeys` | 속성 열거 | `Object.keys()`, `for...in` |
| `getOwnPropertyDescriptor` | 속성 설명자 | `Object.getOwnPropertyDescriptor()` |
| `defineProperty` | 속성 정의 | `Object.defineProperty()` |
| `preventExtensions` | 확장 방지 | `Object.preventExtensions()` |
| `isExtensible` | 확장 가능 여부 | `Object.isExtensible()` |
| `getPrototypeOf` | 프로토타입 가져오기 | `Object.getPrototypeOf()` |
| `setPrototypeOf` | 프로토타입 설정 | `Object.setPrototypeOf()` |
| `apply` | 함수 호출 | `func()`, `func.call()`, `func.apply()` |
| `construct` | 생성자 호출 | `new func()` |

### 트랩 하나가 동작 하나에 대응하지 않는다

위 표는 트랩과 동작을 1:1 로 짝지어 놓았지만 실제로는 그렇지 않다. **`Object.keys` 하나가 트랩 두 개를 거친다.**

```javascript
const p = new Proxy({}, {
  ownKeys(t) { console.log('ownKeys 호출'); return ['a', 'b']; },
  getOwnPropertyDescriptor(t, k) { console.log('gOPD 호출:', k); return undefined; }
});

Object.keys(p);
// ownKeys 호출
// gOPD 호출: a
// gOPD 호출: b
// → []          ← 키를 두 개 돌려줬는데 결과가 비었다
```

`Object.keys` 는 **열거 가능한** 키만 모으는 함수다. 그래서 `ownKeys` 로 이름 목록을 받은 뒤, 키마다 `getOwnPropertyDescriptor` 를 다시 물어 `enumerable` 을 확인한다. 설명자가 `undefined` 면 "그런 속성 없음"으로 판단하고 버린다.

`getOwnPropertyDescriptor` 트랩을 아예 안 만들어도 결과는 같다. 원본 객체에 가서 묻고, 거기에도 없으니 걸러진다.

```javascript
const p = new Proxy({}, { ownKeys() { return ['a', 'b']; } });

Object.keys(p);                    // []            ← 조용히 빈 배열
Object.getOwnPropertyNames(p);     // ['a', 'b']    ← 이쪽은 나온다
```

`getOwnPropertyNames` 는 열거 가능 여부를 따지지 않아서 `ownKeys` 결과를 그대로 준다. **같은 프록시에 물었는데 답이 다르다.** "분명히 키를 돌려줬는데 `Object.keys` 만 비어 있다"로 한참 헤매게 되는 지점이다.

둘을 같이 정의해야 의도대로 동작한다.

```javascript
const p = new Proxy({}, {
  ownKeys() { return ['a', 'b']; },
  getOwnPropertyDescriptor() { return { value: 1, enumerable: true, configurable: true }; }
});

Object.keys(p);        // ['a', 'b']
for (const k in p) {}  // a, b
```

그런데 여기서 끝이 아니다. 값을 실제로 읽는 것은 또 `get` 이다.

```javascript
JSON.stringify(p);   // '{}'
{ ...p };            // { a: undefined, b: undefined }
```

`get` 트랩이 없으니 원본에서 읽어 `undefined` 가 나오고, `JSON.stringify` 는 `undefined` 값을 통째로 빼 버린다. **가짜 속성을 만들어 보이려면 `ownKeys` + `getOwnPropertyDescriptor` + `get` 세 개가 서로 아귀가 맞아야 한다.** 하나만 빠져도 어떤 경로에서는 보이고 어떤 경로에서는 안 보이는 객체가 된다.

`ownKeys` 에도 지켜야 할 불변식이 있다.

```javascript
const t = {};
Object.defineProperty(t, 'must', { value: 1, configurable: false });
Object.keys(new Proxy(t, { ownKeys() { return []; } }));
// TypeError: 'ownKeys' on proxy: trap result did not include 'must'

Object.keys(new Proxy({}, { ownKeys() { return ['a', 'a']; } }));
// TypeError: 'ownKeys' on proxy: trap returned duplicate entries
```

원본에 `configurable: false` 인 속성이 있으면 목록에서 숨길 수 없고, 중복 키도 안 된다. 숨김 프록시를 만들 때 대상에 얼려진 속성이 하나라도 있으면 여기서 걸린다.

반대 방향의 오해도 흔하다. **`get` 트랩은 열거에 전혀 관여하지 않는다.**

```javascript
const p = new Proxy({ real: 1 }, { get(t, k) { return k in t ? t[k] : 'DEFAULT'; } });

p.anything;          // 'DEFAULT'
Object.keys(p);      // ['real']       ← 'anything' 은 없다
JSON.stringify(p);   // '{"real":1}'
```

앞의 "기본값 제공 Proxy" 가 정확히 이 모양이다. 점 표기로 물으면 무엇이든 답하지만 열거하면 원본 그대로다. 그래서 그 객체를 `console.log` 로 찍거나 직렬화해서 넘기면, 코드에서 읽히던 기본값들이 **하나도 안 보인다.** 프록시를 디버깅할 때 출력만 보고 판단하면 안 되는 이유다.

### Proxy 사용 사례

#### 1. 데이터 바인딩
```javascript
// Vue.js의 반응형 시스템과 유사한 구현
function createReactive(obj) {
    const handler = {
        set: function(target, propertyName, value) {
            target[propertyName] = value;
            console.log(`UI 업데이트: ${propertyName} = ${value}`);
            return true;
        }
    };
    
    return new Proxy(obj, handler);
}

const data = createReactive({ count: 0 });
data.count = 1; // "UI 업데이트: count = 1" 출력
```

#### 2. API 래핑
```javascript
// API 호출을 가로채서 캐싱 추가
function createCachedAPI(api) {
    const cache = new Map();
    
    const handler = {
        get: function(target, propertyName) {
            return function(...args) {
                const key = `${propertyName}:${JSON.stringify(args)}`;
                
                if (cache.has(key)) {
                    console.log('캐시에서 반환');
                    return cache.get(key);
                }
                
                const result = target[propertyName].apply(target, args);
                cache.set(key, result);
                console.log('API 호출 후 캐시에 저장');
                return result;
            };
        }
    };
    
    return new Proxy(api, handler);
}
```

### 결론
JavaScript Proxy는 객체의 동작을 가로채서 여러 기능을 덧붙일 수 있는 도구다.
유효성 검사, 로깅, 캐싱, 보안 강화에 쓸 수 있고,
잘 쓰면 코드의 유지보수성과 안정성이 올라간다.
다만 성능에 민감한 자리에서는 조심해서 써야 한다.










## Proxy가 필요한 이유

일반적인 객체 조작에는 이런 제한이 있다.

```javascript
const user = {
    name: '김철수',
    age: 25
};

// 나이를 음수로 설정해도 아무런 제한이 없음
user.age = -10; // 문제가 있어도 막을 수 없음

// 존재하지 않는 속성에 접근해도 undefined만 반환
console.log(user.email); // undefined
```

Proxy를 쓰면 이런 상황을 **미리 감지하고 처리**할 수 있다.
