# tools

## gen_nav.py — 사이드바 메뉴(.pages) 생성기

`Develop/` 아래 모든 `.pages`를 문서 제목에서 다시 만들어낸다.
`.pages` 163개는 전부 이 스크립트의 산출물이므로, 손으로 고치지 말고
여기를 고친 뒤 다시 돌리는 것이 맞다.

```bash
python3 tools/gen_nav.py           # 미리보기 (파일을 쓰지 않는다)
python3 tools/gen_nav.py --write   # 실제로 .pages 를 갱신
mkdocs build                       # 오류 0건인지 확인
```

### 왜 생성하나

awesome-pages는 `nav:`에 `...`이 없으면 **목록에 없는 파일을 메뉴에서 빼버린다.**
손으로 관리하다 실제로 문서 19개가 사이드바에서 사라져 있었다. 빌드는 성공하므로
눈치채기 어렵다. 생성기를 쓰면 디스크에 있는 문서가 빠지는 일이 없다.

### 규칙

1. **파일은 옮기지 않는다.** 메뉴는 `.pages`만으로 바꾼다.
   문서를 옮겨야 한다면 `mkdocs.yml`의 `redirect_maps`에 옛 경로를 남긴다.
2. **상위 디렉터리가 이미 말하는 접두사는 라벨에서 뗀다.**
   `Claude_Code/Claude_Code_Harness.md` → `하네스`.
   단 축약 전후 통틀어 한 번만 뗀다. 두 번 떼면
   `Network Gateway 심화`가 `심화`만 남는다.
3. **부제(`제목 — 부제`)는 사이드바에서만 뗀다.** 문서 제목 자체는 건드리지 않는다.
4. **같은 이름으로 시작하는 형제가 3개 이상이면 그룹으로 접는다.**
   `AWS/Containers`의 `ECS ...` 31개가 그렇게 묶인다.
5. **문서 1개짜리 디렉터리는 부모로 끌어올린다.** 의미 없는 펼침 단계를 없앤다.
   단 최상위 섹션은 흡수 대상이 아니다.
6. **잘라낸 결과가 조사·전치사로 끝나거나 시작하면 되돌린다.**
   `Spring Bean 개념과 사용법` → `Bean 개념과` 같은 파손을 막는다.
7. 형제끼리 라벨이 겹치면 겹치지 않는 **가장 짧은** 후보로 올라간다.
8. 부모 섹션과 같은 이름으로는 묶지 않는다. (`NestJS/NestJS/` 방지)

### MANUAL_GROUPS — 손으로 짜야 하는 곳

자동 규칙은 `crypto`와 `fs`가 '코어 모듈'이라는 걸 알 수 없다. 낱장 문서가
20개 넘게 늘어서는 섹션은 `MANUAL_GROUPS`에 직접 묶음을 적는다.

```python
MANUAL_GROUPS = {
    'Develop/Security': [
        ('암호화', [('AES', 'AES.md'), ('RSA', 'RSA.md'), ...]),
        ...
    ],
}
```

여기 적힌 문서는 자동 배치에서 빠지고, 묶음은 낱장 문서 뒤·하위 섹션 앞에
놓인다. 파일을 옮기지 않으므로 URL은 그대로다. 새 문서를 추가했는데 해당
섹션에 MANUAL_GROUPS가 있다면 거기에도 한 줄 넣어야 묶음 안에 들어간다.

`TITLE_OVERRIDE`는 하위 디렉터리의 `.pages` title을 강제로 바꾼다. 자식의
title이 부모 nav 라벨보다 우선하기 때문에, 섹션 이름을 바꾸려면 여기를 쓴다.

### 문서 제목 규칙

- 기본 문서는 그냥 이름, 깊이 파는 문서는 뒤에 `심화`.
  `가이드` / `심화 가이드` / `Deep Dive` / `완벽 가이드`는 쓰지 않는다.
- frontmatter `tags:`에 `Null`, `null`, `Yes`, `No`, `On`, `Off`를 쓸 때는
  반드시 따옴표를 씌운다. YAML이 불리언·None으로 파싱해 **빌드가 실패한다.**
- 한글 파일명은 NFC로 커밋한다. NFD(자모 분리)로 들어가면 배포 환경에서
  경로가 어긋나 404가 난다.
