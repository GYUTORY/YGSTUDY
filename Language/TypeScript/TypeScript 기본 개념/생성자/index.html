    TypeScript 생성자¶

    개요¶

    TypeScript의 생성자(Constructor)는 객체지향 프로그래밍의 핵심 개념이자, 클래스의 인스턴스를 초기화하는 특별한 메서드다. 이 문서는 생성자를 실제로 어떻게 활용하는지 다룬다.

    생성자의 본질적 특성¶

    생성자에는 일반 메서드에 없는 특성이 있다.

    • 단일성: 클래스당 생성자는 정확히 하나만 정의한다
    • 자동 호출: new 연산자로 인스턴스를 만들면 알아서 실행된다
    • 초기화 전담: 객체의 초기 상태를 안전하게 잡아준다
    • 타입 안전성: TypeScript 타입 시스템이 그대로 적용된다

    생성자가 중요한 이유¶

    1. 객체 생명주기 관리: 객체가 만들어지고 초기화되는 과정을 제어한다
    2. 의존성 주입: 외부 의존성을 안전하게 받아서 쓴다
    3. 불변성 보장: 생성 시점에 객체의 불변 속성을 정한다
    4. 유효성 검증: 객체를 만들기 전에 데이터가 올바른지 확인한다
    5. 메모리 효율성: 필요한 리소스만 할당해 메모리를 아낀다

    핵심 개념¶

    1. 기본 생성자 패턴¶

    생성자의 구조와 역할¶

    생성자는 클래스의 인스턴스를 만들 때 자동으로 호출되는 특별한 메서드다. 일반 메서드와 달리 constructor라는 키워드를 쓰고 반환 타입은 적지 않는다. 생성자는 항상 클래스 인스턴스를 돌려주기 때문이다.

    생성자가 하는 일은 이렇다. - 속성 초기화: 인스턴스의 모든 속성에 초기값을 넣는다 - 유효성 검증: 넘어온 매개변수를 검사해 잘못된 상태의 객체가 만들어지는 걸 막는다 - 의존성 설정: 외부에서 주입받은 의존성을 내부 속성에 넣는다 - 초기 상태 설정: 객체를 바로 쓸 수 있는 상태로 만든다

    표준 생성자 구현¶

    기본 생성자는 클래스의 속성을 초기화한다. 생성자 안에서는 this 키워드로 인스턴스 속성에 접근한다.

    class Person {
    private readonly id: string;
    public name: string;
    public age: number;

    constructor(name: string, age: number) {
        // 유효성 검사: 객체 생성 전 데이터 검증
        if (!name || name.trim().length === 0) {
            throw new Error('이름은 필수입니다.');
        }
        if (age < 0 || age > 150) {
            throw new Error('유효한 나이를 입력해주세요.');
        }

        // 속성 초기화: this를 통해 인스턴스 속성에 접근
        this.id = this.generateId();
        this.name = name.trim();
        this.age = age;
    }

    private generateId(): string {
        return `person_${Date.now()}_${Math.random().toString(36).substr(2, 9)}`;
    }
}

const person = new Person('홍길동', 25);

    매개변수 기본값과 선택적 매개변수¶

    TypeScript에서는 생성자 매개변수에 기본값을 주거나 선택적 매개변수로 지정할 수 있다. 같은 클래스를 여러 방식으로 생성할 수 있어서 그만큼 유연해진다.

    기본값이 있는 매개변수는 = 연산자로 설정하며 그 매개변수를 생략하면 기본값이 들어간다. 선택적 매개변수는 ? 접미사를 붙이며, 타입이 undefined일 수 있다.

    기본값과 선택적 매개변수를 쓸 때 주의할 점: 1. 필수 매개변수는 항상 선택적 매개변수나 기본값이 있는 매개변수보다 앞에 와야 한다 2. 기본값은 컴파일 타임에 평가되므로 함수 호출이나 표현식도 쓸 수 있다 3. 선택적 매개변수는 undefined일 수 있으니 쓰기 전에 항상 확인한다

    class User {
    constructor(
        name: string,              // 필수 매개변수
        email: string,             // 필수 매개변수
        isActive: boolean = true,  // 기본값이 있는 매개변수
        role?: string              // 선택적 매개변수
    ) {
        this.name = name;
        this.email = email;
        this.isActive = isActive;
        this.role = role || 'user'; // 선택적 매개변수는 기본값 처리 필요
    }
}

// 다양한 방식으로 객체 생성 가능
const user1 = new User('김철수', 'kim@example.com');           // isActive = true, role = 'user'
const user2 = new User('이영희', 'lee@example.com', false);    // role = 'user'
const user3 = new User('박민수', 'park@example.com', true, 'admin');

    2. 생성자 오버로드 (Constructor Overloading)¶

    생성자 오버로드는 TypeScript의 타입 시스템을 써서 한 클래스를 여러 매개변수 조합으로 생성하게 해주는 기능이다. 함수 오버로드와 비슷한데 생성자에 맞춰져 있다.

    생성자 오버로드의 필요성과 작동 원리¶

    생성자 오버로드가 필요해지는 상황은 이렇다. - 다양한 입력 형식 지원: 개별 매개변수와 객체 형식을 모두 지원해야 할 때 - 선택적 속성의 조합: 일부 속성은 필수이고 일부는 선택적일 때 - API 사용성 향상: 사용자가 여러 방식으로 객체를 만들게 하고 싶을 때

    오버로드의 작동 방식: 1. 오버로드 시그니처: 타입 정보만 있는 선언부다. 컴파일러가 타입 체크에 쓴다 2. 구현 시그니처: 실제로 실행되는 코드가 들어가는 생성자 구현부다 3. 타입 가드: 구현부에서 매개변수 타입을 검사해 맞는 로직을 실행한다

    기본 오버로드 패턴¶

    오버로드 시그니처에는 타입 정보만, 구현 시그니처에는 실제 로직이 들어간다. TypeScript 컴파일러는 호출 시점에 넘어온 인자의 타입을 보고 맞는 오버로드 시그니처를 골라 타입 체크를 한다.

    class Employee {
    public name: string;
    public age: number;
    public email?: string;
    public department: string;

    // 오버로드 시그니처들: 타입 정의만 제공
    constructor(name: string, age: number);
    constructor(name: string, age: number, email: string);
    constructor(name: string, age: number, email: string, department: string);

    // 구현 시그니처: 실제 실행되는 코드
    constructor(
        name: string, 
        age: number, 
        email?: string, 
        department: string = 'General'
    ) {
        this.name = name;
        this.age = age;
        this.email = email;
        this.department = department;
    }
}

// 다양한 방식으로 객체 생성 가능
const emp1 = new Employee('홍길동', 25);
const emp2 = new Employee('김철수', 30, 'kim@company.com');
const emp3 = new Employee('이영희', 28, 'lee@company.com', 'IT');

    고급 오버로드 패턴 - 객체와 개별 매개변수 혼합¶

    복잡한 시나리오에서는 개별 매개변수와 객체를 둘 다 받도록 오버로드를 설계하기도 한다. 이때는 구현부에서 typeof 연산자나 타입 가드로 매개변수의 타입을 가려내야 한다.

    이 패턴의 장점: - API 일관성: 기존 코드와의 호환성 유지 (개별 매개변수) - 확장성: 새 속성이 추가돼도 객체 방식으로 쉽게 대응 (객체 매개변수) - 가독성: 매개변수가 많을 때는 객체 방식이 더 명확하다

    주의사항: - 구현부의 타입 가드를 명확하게 작성해야 한다 - 모든 오버로드 시그니처를 감당할 수 있는 구현부가 필요하다 - 타입 안전성을 지키려면 타입 단언이 필요할 때도 있다

    class Product {
    public id: string;
    public name: string;
    public price: number;
    public category: string;

    // 개별 매개변수와 객체 모두 지원
    constructor(id: string, name: string, price: number);
    constructor(id: string, name: string, price: number, category: string);
    constructor(productData: ProductData);

    // 구현부: 타입 가드로 분기 처리
    constructor(
        idOrData: string | ProductData,
        name?: string,
        price?: number,
        category?: string
    ) {
        if (typeof idOrData === 'string') {
            // 개별 매개변수 방식
            this.id = idOrData;
            this.name = name!;
            this.price = price!;
            this.category = category || 'General';
        } else {
            // 객체 방식
            this.id = idOrData.id;
            this.name = idOrData.name;
            this.price = idOrData.price;
            this.category = idOrData.category || 'General';
        }
    }
}

interface ProductData {
    id: string;
    name: string;
    price: number;
    category?: string;
}

// 두 가지 방식 모두 사용 가능
const product1 = new Product('P001', '노트북', 1500000);
const product2 = new Product({ id: 'P002', name: '마우스', price: 50000 });

    3. 매개변수 속성 (Parameter Properties)¶

    매개변수 속성은 TypeScript에만 있는 독특한 기능이다. 생성자 매개변수에 접근 제한자(public, private, protected)나 readonly를 붙이면, 컴파일러가 알아서 클래스 속성을 선언하고 초기화한다.

    매개변수 속성의 개념과 장점¶

    보통은 생성자에서 매개변수를 받아 인스턴스 속성에 할당하는 코드를 직접 쓴다. 매개변수 속성을 쓰면 그 과정이 자동으로 처리된다.

    전통적인 방식: 

    class User {
    public name: string;
    public email: string;

    constructor(name: string, email: string) {
        this.name = name;    // 중복된 할당 코드
        this.email = email; // 중복된 할당 코드
    }
}

    매개변수 속성 방식: 

    class User {
    // 매개변수 속성을 사용하면 위의 선언과 할당이 자동으로 이루어짐
    constructor(
        public name: string,
        public email: string
    ) {}
}

    두 방식은 컴파일 결과가 같다. 대신 매개변수 속성 쪽이 코드가 짧다.

    기본 매개변수 속성 패턴¶

    매개변수 속성은 접근 제한자와 같이 쓰고 readonly도 함께 붙일 수 있다:

    • public: 외부에서 접근 가능한 공개 속성
    • private: 클래스 내부에서만 접근 가능한 비공개 속성
    • protected: 클래스와 하위 클래스에서 접근 가능한 보호된 속성
    • readonly: 초기화 후 변경 불가능한 읽기 전용 속성
    class SecureUser {
    // 매개변수 속성으로 자동 생성되는 속성들
    constructor(
        public readonly id: string,        // public readonly 속성 자동 생성
        public name: string,                // public 속성 자동 생성
        private password: string,          // private 속성 자동 생성
        protected role: string = 'user'   // protected 속성 (기본값 포함)
    ) {
        // 여기서는 유효성 검사 등 추가 로직만 수행
        this.validateUser();
    }

    private validateUser(): void {
        // 유효성 검사 로직
    }
}

const user = new SecureUser('user_123', '홍길동', 'password', 'admin');
console.log(user.name);  // 접근 가능 (public)
// console.log(user.password); // 에러: private 속성

    읽기 전용 속성과 불변성¶

    readonly와 함께 쓰면 생성 시점에 한 번만 설정되고 그 뒤로는 못 바꾸는 불변 속성이 된다. 객체의 불변성을 보장할 때 유용하다.

    불변성의 장점: - 안전성: 의도하지 않은 수정 방지 - 예측 가능성: 객체의 상태가 변하지 않아 디버깅이 쉽다 - 스레드 안전성: 동시성 환경에서 안전

    class AppConfiguration {
    constructor(
        public readonly apiUrl: string,           // 변경 불가능
        public readonly timeout: number,          // 변경 불가능
        public readonly retries: number = 3       // 기본값과 함께 readonly
    ) {
        this.validateConfiguration();
    }

    private validateConfiguration(): void {
        // 설정 검증 로직
    }
}

const config = new AppConfiguration('https://api.example.com', 5000);
// config.apiUrl = 'https://new-url.com'; // 컴파일 에러! readonly 속성은 변경 불가

    매개변수 속성 사용 시 주의사항¶

    1. 명시적 선언과 혼용 금지: 매개변수 속성으로 자동 생성되는 속성을 따로 또 선언하면 안 된다
    2. 컴파일 결과: JavaScript로 컴파일되면 일반 속성과 똑같이 변환된다 (TypeScript만의 문법)
    3. 가독성: 속성을 전부 매개변수 속성으로 만들면 생성자 시그니처가 길어지니, 골라서 써야 한다

    실전 활용 사례¶

    1. 의존성 주입 패턴¶

    의존성 주입(Dependency Injection)은 생성자로 외부 의존성을 주입받는 패턴이다. 객체 사이의 결합도를 낮추고 테스트 가능성을 높이는 중요한 설계 기법이다.

    의존성 주입의 장점: - 느슨한 결합: 클래스가 구체적인 구현이 아닌 인터페이스에 의존 - 테스트 용이성: Mock 객체를 주입해 단위 테스트를 돌리기 쉽다 - 유연성: 런타임에 다른 구현으로 교체 가능

    interface DatabaseConfig {
    host: string;
    port: number;
    database: string;
}

class DatabaseConnectionManager {
    constructor(
        private config: DatabaseConfig,  // 의존성을 생성자에서 주입
        private maxRetries: number = 3
    ) {
        this.validateConfiguration();
    }

    private validateConfiguration(): void {
        // 설정 검증 로직
    }
}

// 외부에서 설정 객체를 주입
const config: DatabaseConfig = {
    host: 'localhost',
    port: 5432,
    database: 'production_db'
};

const dbManager = new DatabaseConnectionManager(config);

    2. 설정 객체 패턴¶

    생성자에 매개변수가 많이 필요하면 설정 객체로 묶는 편이 읽기도 낫고 고치기도 쉽다. 특히 선택적 매개변수가 많을 때 효과가 크다.

    설정 객체 패턴의 장점: - 가독성: 매개변수의 의미가 명확하다 - 확장성: 새 설정을 추가하기 쉽다 - 선택적 속성: 필요한 속성만 전달 가능

    interface ApiClientConfig {
    baseUrl: string;
    apiKey?: string;
    timeout?: number;
    retries?: number;

    2. 고급 디자인 패턴과 생성자¶

    팩토리 패턴과 생성자¶

    팩토리 패턴은 객체 생성을 캡슐화해서, 클라이언트가 생성자를 직접 호출하지 않고 팩토리 메서드로 객체를 만들게 하는 패턴이다. 이 패턴에서 생성자는 팩토리 메서드 안에서 호출된다.

    팩토리 패턴의 장점: - 유연성: 객체 생성 로직이 한곳에 모여 있어 변경이 쉽다 - 확장성: 새 타입을 추가하기 쉽다 - 복잡성 감소: 클라이언트는 구체적인 클래스에 의존하지 않는다

    // 추상 기본 클래스
abstract class Vehicle {
    constructor(
        protected brand: string,
        protected model: string,
        protected year: number
    ) {}

    abstract getInfo(): string;
}

// 구체 클래스들
class Car extends Vehicle {
    constructor(brand: string, model: string, year: number) {
        super(brand, model, year);
    }
    getInfo(): string {
        return `${this.brand} ${this.model} (${this.year})`;
    }
}

// 팩토리 클래스
class VehicleFactory {
    static create(type: 'car' | 'motorcycle', brand: string, model: string, year: number): Vehicle {
        switch (type) {
            case 'car':
                return new Car(brand, model, year);
            // 다른 타입들...
        }
    }
}

// 팩토리를 통한 객체 생성
const vehicle = VehicleFactory.create('car', '현대', '아반떼', 2023);

    싱글톤 패턴과 생성자¶

    싱글톤 패턴은 클래스의 인스턴스가 오직 하나만 존재하도록 보장하는 패턴이다. 생성자를 private로 막아 외부에서 직접 만들지 못하게 하고 정적 메서드로 그 하나뿐인 인스턴스에 접근한다.

    싱글톤 패턴의 특징: - 단일 인스턴스: 애플리케이션 전체에서 하나의 인스턴스만 존재 - 전역 접근: 어디서나 동일한 인스턴스에 접근 가능 - 지연 초기화: 최초 사용 시점에 인스턴스 생성

    class ApplicationLogger {
    private static instance: ApplicationLogger;

    // 생성자를 private로 선언하여 외부 접근 차단
    private constructor(
        private logLevel: string = 'INFO'
    ) {
        // 초기화 로직
    }

    // 정적 메서드를 통한 단일 인스턴스 접근
    static getInstance(logLevel?: string): ApplicationLogger {
        if (!ApplicationLogger.instance) {
            ApplicationLogger.instance = new ApplicationLogger(logLevel);
        }
        return ApplicationLogger.instance;
    }

    log(message: string): void {
        // 로깅 로직
    }
}

// 항상 같은 인스턴스 반환
const logger1 = ApplicationLogger.getInstance('DEBUG');
const logger2 = ApplicationLogger.getInstance(); // logger1과 동일한 인스턴스

    주의사항: 싱글톤 패턴은 전역 상태를 만든다. 그만큼 테스트가 어려워지니 꼭 필요한 경우에만 쓴다.

    성능 최적화 및 모범 사례¶

    1. 생성자 성능 최적화¶

    생성자는 객체를 만들 때마다 호출된다. 그래서 생성자 안에서 무거운 작업을 하면 객체 생성이 느려진다. 생성자에서는 최소한의 초기화만 하고 나머지는 지연 초기화(Lazy Initialization) 패턴으로 미루는 편이 좋다.

    지연 초기화 패턴의 개념: 무거운 리소스나 계산이 필요한 데이터를 생성자에서 초기화하지 않고 그 리소스가 실제로 필요한 시점에 초기화하는 패턴이다. 객체 생성 시간이 줄고 메모리도 효율적으로 쓴다.

    class DataProcessor {
    private _expensiveCache: Map<string, any> | null = null;

    constructor(public readonly dataSource: string) {
        // 생성자에서는 가벼운 초기화만
        this.validateDataSource();
    }

    // 지연 초기화: 실제 사용 시점에 초기화
    private get expensiveCache(): Map<string, any> {
        if (!this._expensiveCache) {
            this._expensiveCache = new Map();
            // 무거운 초기화 작업은 여기서 수행
        }
        return this._expensiveCache;
    }

    public processData(): void {
        // 캐시에 접근할 때 초기화됨
        const cache = this.expensiveCache;
    }
}

    2. 에러 처리 및 복구¶

    생성자에서 날 수 있는 오류를 제대로 처리해야 애플리케이션이 안정적으로 돈다. 생성자는 객체의 초기 상태를 설정하는 중요한 단계라서, 실패하면 명확한 에러 메시지와 함께 예외를 던지거나 폴백 메커니즘을 두는 쪽으로 간다.

    생성자 에러 처리 원칙: - 조기 실패(Fail Fast): 잘못된 상태의 객체가 만들어지는 걸 방지 - 명확한 에러 메시지: 무엇이 잘못됐는지 명확히 알려줌 - 폴백 전략: 일부 설정이 실패해도 기본값으로 동작 가능하게

    class ServiceManager {
    constructor(
        private config: ServiceConfig,
        private fallbackConfig?: ServiceConfig
    ) {
        try {
            this.validateConfig();
        this.initializeServices();
            } catch (error) {
            // 기본 설정으로 폴백
            if (this.fallbackConfig) {
                this.config = this.fallbackConfig;
                this.initializeServices();
                } else {
                throw new Error(`서비스 초기화 실패: ${error.message}`);
            }
        }
    }

    private validateConfig(): void {

    }
}

    주요 내용¶

    1. 타입 안전성: TypeScript의 타입 시스템과 맞물려 컴파일 타임에 오류를 잡는다
    2. 유연성: 생성자 오버로드로 다양한 객체 생성 방식을 지원한다
    3. 확장성: 매개변수 속성과 디자인 패턴으로 유지보수 가능한 코드를 짠다
    4. 견고성: 유효성 검사와 에러 처리로 안정적인 애플리케이션을 만든다
    5. 성능: 지연 초기화와 최적화 기법으로 리소스를 효율적으로 관리한다

    실무 적용 가이드¶

    • 엔터프라이즈 환경: 의존성과 설정이 복잡한 대규모 애플리케이션일수록 생성자의 역할이 커진다
    • 마이크로서비스: 각 서비스의 독립적인 초기화와 설정 관리
    • 테스트: 생성자로 의존성을 주입해 테스트 가능한 코드 작성
    • 성능: 대용량 데이터 처리 시 지연 초기화와 메모리 최적화

    생성자를 제대로 쓰면 더 안전하고, 유지보수하기 쉬우며, 확장 가능한 TypeScript 애플리케이션을 만들 수 있다.
