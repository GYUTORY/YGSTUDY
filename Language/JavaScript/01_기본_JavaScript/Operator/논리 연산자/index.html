    JavaScript 논리 연산자 개념과 사용법¶

    배경¶

    JavaScript에서 논리 연산자는 조건문을 결합하거나 값을 평가하는 데 사용되는 중요한 연산자들입니다. 주요 논리 연산자로는 &&(AND), ||(OR), !(NOT)이 있으며, 단축 평가(Short-circuit evaluation)를 통해 효율적인 코드를 작성할 수 있습니다.

    논리 연산자의 필요성¶

    • 조건 결합: 여러 조건을 논리적으로 결합
    • 값 평가: 표현식의 참/거짓 판단
    • 단축 평가: 불필요한 연산 방지
    • 기본값 설정: falsy 값 처리

    기본 개념¶

    • AND (&&): 모든 조건이 참일 때만 참
    • OR (||): 하나라도 참이면 참
    • NOT (!): 값을 반전
    • 단축 평가: 첫 번째 피연산자로 결과 결정

    핵심¶

    1. AND 연산자 (&&)¶

    기본 동작¶

    // 두 개 이상의 조건이 모두 참일 때만 true 반환
const a = true;
const b = false;
const c = true;

console.log(a && b);    // false
console.log(a && c);    // true
console.log(b && c);    // false
console.log(a && b && c); // false

    단축 평가¶

    // 왼쪽 피연산자가 false이면 오른쪽은 평가하지 않음
const result = false && someFunction(); // someFunction()은 호출되지 않음

// 실제 사용 예시
const user = null;
const name = user && user.name; // user가 null이므로 user.name은 평가되지 않음
console.log(name); // null

    여기서 name 이 false 가 아니라 null 인 것에 주목할 만하다. && 와 || 는 boolean 을 돌려주지 않는다. 평가를 멈춘 그 자리의 값을 그대로 돌려준다.

    0 && 'X'      // 0
'' && 'X'     // ''
null && 'X'   // null
NaN && 'X'    // NaN

    이게 화면에 그대로 새어 나오는 곳이 JSX 다. {count && <List/>} 를 쓰면 count 가 0 일 때 리스트 대신 숫자 0 이 렌더된다. 아무것도 안 나오길 기대했는데 화면 구석에 0 이 찍히는 버그가 여기서 나온다. {count > 0 && <List/>} 처럼 조건을 명시적으로 boolean 으로 만들면 막힌다.

    타입이 섞이는 것도 문제다. user && user.name 의 타입은 "문자열 또는 null 또는 undefined 또는 사용자가 넣은 falsy 값 전부"라서, 이 값을 그대로 다음 함수에 넘기면 받는 쪽이 감당해야 할 경우의 수가 늘어난다.

    실제 활용¶

    // 조건부 렌더링
const isAdmin = true;
const isLoggedIn = true;

if (isAdmin && isLoggedIn) {
    console.log("관리자 대시보드에 접근합니다.");
}

// 안전한 객체 속성 접근
const user = {
    profile: {
        name: 'Alice',
        age: 25
    }
};

const userName = user && user.profile && user.profile.name;
console.log(userName); // 'Alice'

// 조건부 함수 실행
function showAdminPanel() {
    console.log('관리자 패널 표시');
}

const isAdmin = true;
const hasPermission = true;

isAdmin && hasPermission && showAdminPanel(); // 조건이 모두 참일 때만 실행

    이 블록은 그대로 붙여넣으면 실행되지 않는다. const isAdmin 이 위아래로 두 번 선언돼 있다.

    SyntaxError: Identifier 'isAdmin' has already been declared

    const/let 의 재선언은 런타임 에러가 아니라 파싱 단계에서 걸리는 문법 에러다. 그래서 위쪽 줄이 정상이더라도 파일 전체가 한 줄도 실행되지 않는다. var 였다면 조용히 덮어쓰고 넘어갔을 것이다.

    블로그나 문서의 예제를 이어 붙여 쓸 때 실제로 자주 만나는 상황이다. 에러 메시지가 가리키는 줄만 보면 멀쩡해 보여서, 같은 이름이 위에 또 있는지를 찾아야 한다.

    2. OR 연산자 (||)¶

    기본 동작¶

    // 여러 조건 중 하나라도 참이면 true 반환
const isRaining = false;
const isSnowing = true;
const isCloudy = false;

console.log(isRaining || isSnowing);    // true
console.log(isRaining || isCloudy);     // false
console.log(isRaining || isSnowing || isCloudy); // true

    단축 평가¶

    // 왼쪽 피연산자가 true이면 오른쪽은 평가하지 않음
const result = true || someFunction(); // someFunction()은 호출되지 않음

// 실제 사용 예시
const defaultName = "Guest";
const userName = user.name || defaultName; // user.name이 falsy면 defaultName 사용

    실제 활용¶

    // 기본값 설정
const userName = user.name || "익명 사용자";
const userAge = user.age || 0;
const userEmail = user.email || "이메일 없음";

// 조건부 실행
function showWelcomeMessage() {
    console.log('환영합니다!');
}

function showLoginMessage() {
    console.log('로그인이 필요합니다.');
}

const isLoggedIn = false;
isLoggedIn ? showWelcomeMessage() : showLoginMessage();

// 또는 OR 연산자 사용
(isLoggedIn && showWelcomeMessage) || showLoginMessage();

    마지막 줄은 삼항 연산자와 같지 않다. 로그인한 사용자에게는 아무 일도 일어나지 않는다.

    let isLoggedIn = true;
(isLoggedIn && showWelcomeMessage) || showLoginMessage();
// 아무것도 출력되지 않는다

isLoggedIn = false;
(isLoggedIn && showWelcomeMessage) || showLoginMessage();
// '로그인이 필요합니다.'

    showWelcomeMessage 뒤에 () 가 없다. 함수 참조일 뿐이고, 함수 객체는 언제나 truthy 라서 || 는 거기서 멈춘다. 환영 메시지는 호출되지 않고, 로그인 메시지는 막힌다. 두 갈래 중 어느 쪽도 실행되지 않는데 에러는 나지 않는다.

    거짓 갈래만 눌러보면 잘 동작하는 것처럼 보이는 것이 이 버그의 성질이다. 참 갈래는 "조용하다"가 정상 동작인지 아닌지 구분이 안 된다.

    () 를 붙여 고쳐도 문제가 남는다. 환영 메시지 함수가 undefined 를 돌려주면(대부분 그렇다) || 가 falsy 로 보고 로그인 메시지까지 이어서 실행한다. 분기를 논리 연산자로 흉내내면 반환값이 제어 흐름에 끼어든다. 분기는 if 나 삼항으로 쓴다.

    3. NOT 연산자 (!)¶

    기본 동작¶

    // 값을 반전시킴 (true는 false로, false는 true로)
const isLoggedIn = true;
console.log(!isLoggedIn);     // false
console.log(!!isLoggedIn);    // true (이중 부정)

// 다양한 값에 대한 NOT 연산
console.log(!true);      // false
console.log(!false);     // true
console.log(!0);         // true
console.log(!1);         // false
console.log(!"");        // true
console.log(!"hello");   // false
console.log(!null);      // true
console.log(!undefined); // true
console.log(!{});        // false
console.log(![]);        // false

    실제 활용¶

    // 조건 반전
const isDisabled = false;
const isEnabled = !isDisabled; // true

// 필수 입력 검증
const username = "";
const password = "123456";

if (!username || !password) {
    console.log("사용자명과 비밀번호를 모두 입력해주세요.");
}

// 존재 여부 확인
const user = null;
if (!user) {
    console.log("사용자를 찾을 수 없습니다.");
}

// 타입 변환 (boolean으로)
const truthyValue = "hello";
const falsyValue = "";

console.log(!!truthyValue); // true
console.log(!!falsyValue);  // false

    4. 복합 논리 연산¶

    우선순위¶

    // NOT > AND > OR 순서로 평가
const result = !true && false || true;
// 1. !true = false
// 2. false && false = false
// 3. false || true = true
console.log(result); // true

// 괄호를 사용하여 명확하게 표현
const result2 = (!true && false) || true;
console.log(result2); // true

    복잡한 조건¶

    const age = 20;
const hasID = true;
const hasPermission = true;
const isVIP = false;

// 복합 조건
if (age >= 18 && hasID && (hasPermission || isVIP)) {
    console.log("접근이 허용됩니다.");
}

// 가독성을 위한 변수 분리
const isAdult = age >= 18;
const hasValidID = hasID;
const hasAccess = hasPermission || isVIP;

if (isAdult && hasValidID && hasAccess) {
    console.log("접근이 허용됩니다.");
}

    예시¶

    1. 실제 사용 사례¶

    폼 검증¶

    function validateForm(formData) {
    const { username, email, password, confirmPassword } = formData;

    // 각 필드 검증
    const isUsernameValid = username && username.length >= 3;
    const isEmailValid = email && email.includes('@');
    const isPasswordValid = password && password.length >= 6;
    const doPasswordsMatch = password === confirmPassword;

    // 전체 폼 유효성 검사
    const isFormValid = isUsernameValid && isEmailValid && isPasswordValid && doPasswordsMatch;

    if (!isFormValid) {
        console.log('폼 검증 실패:');
        if (!isUsernameValid) console.log('- 사용자명은 3자 이상이어야 합니다.');
        if (!isEmailValid) console.log('- 유효한 이메일을 입력해주세요.');
        if (!isPasswordValid) console.log('- 비밀번호는 6자 이상이어야 합니다.');
        if (!doPasswordsMatch) console.log('- 비밀번호가 일치하지 않습니다.');
    }

    return isFormValid;
}

// 사용 예시
const formData = {
    username: 'alice',
    email: 'alice@example.com',
    password: '123456',
    confirmPassword: '123456'
};

const isValid = validateForm(formData);
console.log('폼 유효성:', isValid);

    권한 검사¶

    function checkPermission(user, action) {
    // 사용자 기본 권한
    const hasBasicPermission = user && user.isActive;

    // 관리자 권한
    const isAdmin = user && user.role === 'admin';

    // 특정 권한
    const hasSpecificPermission = user && user.permissions && user.permissions.includes(action);

    // VIP 사용자
    const isVIP = user && user.isVIP;

    // 최종 권한 결정
    const hasPermission = hasBasicPermission && (isAdmin || hasSpecificPermission || isVIP);

    return hasPermission;
}

// 사용 예시
const user = {
    id: 1,
    name: 'Alice',
    isActive: true,
    role: 'user',
    permissions: ['read', 'write'],
    isVIP: false
};

console.log('읽기 권한:', checkPermission(user, 'read')); // true
console.log('삭제 권한:', checkPermission(user, 'delete')); // false

    2. 고급 패턴¶

    조건부 객체 속성¶

    function createUserConfig(user) {
    return {
        name: user.name || 'Anonymous',
        email: user.email || 'no-email@example.com',
        role: user.role || 'user',
        // 조건부 속성 추가
        ...(user.isAdmin && { permissions: ['all'] }),
        ...(user.isVIP && { vipLevel: user.vipLevel }),
        ...(user.avatar && { avatarUrl: user.avatar })
    };
}

// 사용 예시
const user1 = { name: 'Alice', isAdmin: true };
const user2 = { name: 'Bob', isVIP: true, vipLevel: 2, avatar: 'avatar.webp' };

console.log(createUserConfig(user1));
console.log(createUserConfig(user2));

    함수형 프로그래밍¶

    // 조건부 함수 실행
function executeIf(condition, fn) {
    return condition && fn();
}

function logMessage(message) {
    console.log(message);
}

// 사용 예시
const isDebugMode = true;
const isProduction = false;

executeIf(isDebugMode, () => logMessage('디버그 모드입니다.'));
executeIf(isProduction, () => logMessage('프로덕션 모드입니다.'));

// 파이프라인에서의 사용
function processData(data) {
    return data
        .filter(item => item && item.isValid)
        .map(item => ({
            ...item,
            processed: true,
            timestamp: Date.now()
        }))
        .filter(item => item.timestamp > 0);
}

    운영 팁¶

    성능 최적화¶

    단축 평가 활용¶

    // 비효율적인 방법
function expensiveOperation() {
    console.log('비용이 많이 드는 연산');
    return true;
}

// 조건이 false인 경우에도 실행됨
if (false && expensiveOperation()) {
    console.log('실행되지 않음');
}

// 효율적인 방법: 단축 평가 활용
if (false && expensiveOperation()) {
    console.log('실행되지 않음');
}
// expensiveOperation()은 호출되지 않음

    위 예제의 "비효율적인 방법"과 "효율적인 방법"은 글자 하나 다르지 않은 같은 코드다. 둘 다 if (false && expensiveOperation()) 이고, 둘 다 expensiveOperation() 을 호출하지 않는다. 주석만 반대로 달려 있다.

    단축 평가는 켜고 끌 수 있는 최적화가 아니라 && 와 || 의 정의 자체다. 그래서 "단축 평가를 활용해 성능을 개선한다"는 표현은 성립하지 않는다 — 다른 선택지가 없다.

    실제로 의미가 있는 것은 피연산자 순서다. 그리고 그건 성능보다 안전 문제로 먼저 나타난다.

    user.profile.name && user     // user 가 null 이면 여기서 터진다
user && user.profile.name     // 안전하다

    && 는 왼쪽이 오른쪽의 실행 조건이라는 뜻을 담고 있다. 순서를 바꾸면 조건이 사라진다. "싼 검사를 앞에 두라"는 조언보다 "뒤 항이 앞 항에 의존하면 순서를 바꾸지 말라"가 먼저다.

    조건 최적화¶

    // 비효율적인 조건 순서
function checkCondition() {
    console.log('조건 검사');
    return false;
}

function checkAnotherCondition() {
    console.log('다른 조건 검사');
    return true;
}

// false가 먼저 나오는 경우
if (checkCondition() && checkAnotherCondition()) {
    console.log('실행됨');
}

// true가 먼저 나오는 경우
if (checkAnotherCondition() && checkCondition()) {
    console.log('실행됨');
}

    에러 처리¶

    안전한 속성 접근¶

    // 안전하지 않은 방법
function getUserName(user) {
    return user.name; // user가 null이면 오류 발생
}

// 안전한 방법
function getUserNameSafe(user) {
    return user && user.name;
}

// 더 안전한 방법
function getUserNameSafest(user) {
    return user && user.name || 'Unknown';
}

// 사용 예시
const user = null;
console.log(getUserNameSafe(user)); // null
console.log(getUserNameSafest(user)); // 'Unknown'

    "더 안전한 방법"이 정말 더 안전한지는 user 가 있을 때 확인해야 한다.

    getUserNameSafest({ name: '' });   // 'Unknown'  ← 빈 이름을 이름 없음으로 바꿨다
getUserNameSafest({ name: 0 });    // 'Unknown'

    || 는 null·undefined 뿐 아니라 falsy 전부를 기본값으로 갈아치운다. 이름이 빈 문자열인 것과 사용자 자체가 없는 것은 다른 상황인데 결과가 같아진다. 같은 문제가 문서 앞쪽 user.age || 0 에도 있다 — 나이가 0 인 사람과 나이를 모르는 사람이 구분되지 않는다.

    user.age || 18     // age 가 0 이면 18
user.age ?? 18     // age 가 0 이면 0. null/undefined 일 때만 18

    숫자와 문자열 필드의 기본값은 ?? 로 쓴다. || 가 맞는 자리는 "0 도 빈 문자열도 없는 값으로 취급하겠다"고 의도한 경우뿐이고, 그런 경우는 생각보다 드물다.

    두 연산자를 괄호 없이 섞으면 문법 에러가 난다.

    const x = null || undefined ?? 1;
// SyntaxError: Unexpected token '??'

    우선순위가 헷갈릴 자리라 언어 차원에서 괄호를 강제한 것이다.

    속성 접근이 목적이라면 user && user.profile && user.profile.name 대신 user?.profile?.name 을 쓴다. 짧아지는 것보다 중요한 것은 결과가 undefined 로 통일된다는 점이다. && 체인은 중간에 걸린 값(null, 0, '')을 그대로 돌려주지만 옵셔널 체이닝은 언제나 undefined 다. 그래서 ?? 기본값 과 자연스럽게 이어진다.

    조건부 함수 실행¶

    // 안전한 함수 호출
function safeExecute(fn, ...args) {
    return typeof fn === 'function' && fn(...args);
}

// 사용 예시
const callback = null;
const validCallback = () => console.log('실행됨');

safeExecute(callback); // 아무것도 실행되지 않음
safeExecute(validCallback); // '실행됨' 출력

    논리 연산자 우선순위¶

    연산자 우선순위 설명
    ! 1 NOT (가장 높음)
    && 2 AND
    || 3 OR (가장 낮음)

    Falsy 값들¶

    값 타입 설명
    false Boolean 거짓
    0 Number 숫자 0
    -0 Number 음수 0
    0n BigInt BigInt 0
    "" String 빈 문자열
    null null null 값
    undefined undefined 정의되지 않음
    NaN Number 숫자가 아님

    논리 연산자 사용 권장사항¶

    상황 권장사항 이유
    조건 결합 && 사용 모든 조건 만족 필요
    기본값 설정 || 사용 falsy 값 처리
    조건 반전 ! 사용 명확한 부정 표현
    복잡한 조건 괄호 사용 우선순위 명확화
    성능 중요 단축 평가 활용 불필요한 연산 방지

    결론¶

    논리 연산자는 JavaScript에서 조건을 결합하고 값을 평가하는 핵심 도구입니다. 단축 평가를 활용하여 효율적인 코드를 작성하세요. AND 연산자는 모든 조건이 참일 때, OR 연산자는 하나라도 참일 때 사용하세요. NOT 연산자로 값을 반전시키고 boolean 변환을 할 수 있습니다. 복잡한 조건에서는 괄호를 사용하여 우선순위를 명확히 하세요. 논리 연산자를 활용하여 안전하고 읽기 쉬운 코드를 작성하세요.
