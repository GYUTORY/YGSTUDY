    중첩 클래스 (Nested Classes)¶

    클래스 안에 클래스를 정의하는 문법이다. 유형은 네 가지다.

    유형 static 여부 선언 위치
    정적 중첩 클래스 O 외부 클래스 멤버 위치
    멤버 내부 클래스 X 외부 클래스 멤버 위치
    지역 클래스 X 메서드·블록 안
    익명 클래스 X 지역 클래스의 이름 없는 버전

    중첩(Nested)과 내부(Inner)는 다른 관계를 말한다. 정적 중첩 클래스는 외부 클래스 안에 있을 뿐 외부 클래스와 무관한 독립 클래스다. 멤버 내부 클래스는 외부 클래스를 구성하는 요소다.

    정적 중첩 클래스 (Static Nested Class)¶

    static을 붙이면 외부 클래스 인스턴스와 관계없이 독립적으로 동작한다. 외부 클래스의 static 멤버에만 접근할 수 있다.

    class OuterClass {
    private static int staticValue = 10;

    static class StaticNestedClass {
        void display() {
            System.out.println("static value: " + staticValue);
        }
    }
}

public class Main {
    public static void main(String[] args) {
        OuterClass.StaticNestedClass nested = new OuterClass.StaticNestedClass();
        nested.display();
    }
}

    외부 인스턴스를 만들지 않아도 된다. 네 가지 중 가장 가볍고 부작용이 없다.

    멤버 내부 클래스 (Member Inner Class)¶

    static 없이 외부 클래스 안에 선언한다. 외부 클래스의 모든 멤버(private 포함)에 접근할 수 있다.

    class OuterClass {
    private int value = 10;

    class MemberInnerClass {
        void display() {
            System.out.println("value: " + value);
        }
    }
}

public class Main {
    public static void main(String[] args) {
        OuterClass outer = new OuterClass();
        OuterClass.MemberInnerClass inner = outer.new MemberInnerClass();
        inner.display();
    }
}

    this$0 — 숨겨진 외부 참조¶

    비정적 내부 클래스를 컴파일하면 JVM이 this$0라는 합성(synthetic) 필드를 자동으로 추가한다. 이 필드는 외부 클래스 인스턴스를 가리키는 강한 참조다.

    // 컴파일 후 실제 바이트코드 구조
class OuterClass$MemberInnerClass {
    final OuterClass this$0;  // 자동 생성

    OuterClass$MemberInnerClass(OuterClass outer) {
        this.this$0 = outer;
    }
}

    내부 클래스 인스턴스가 살아있으면 외부 클래스 인스턴스도 GC가 수거하지 못한다. 내부 클래스 인스턴스를 컬렉션에 담거나 스레드에 넘기거나 리스너로 등록하면 외부 인스턴스가 예상보다 훨씬 오래 살아남는다.

    외부 인스턴스를 참조할 필요가 없는데 멤버 내부 클래스를 쓰면 이 문제가 생긴다. 그 경우엔 static을 붙인다.

    지역 클래스 (Local Class)¶

    메서드나 블록 안에 선언한다. 선언된 블록 범위 안에서만 쓸 수 있다.

    class OuterClass {
    void process() {
        int localVar = 10; // effectively final

        class LocalClass {
            void show() {
                System.out.println("localVar: " + localVar);
            }
        }

        LocalClass local = new LocalClass();
        local.show();
    }
}

    effectively final 제약¶

    지역 클래스는 외부 메서드의 지역 변수를 캡처할 수 있다. 캡처 시점에 값을 복사한다. final 또는 effectively final(선언 후 변경되지 않은 변수)이어야 한다.

    이 제약은 일관성 문제 때문에 생겼다. 지역 변수는 스택에 살고 메서드 종료 후 사라진다. 내부 클래스 인스턴스는 메서드 종료 후에도 살아남을 수 있다. 값을 복사해 두면 원본이 사라져도 접근할 수 있지만, 원본이 나중에 바뀌면 복사본과 불일치가 생긴다. Java는 그 불일치를 허용하지 않으려 변경 가능한 변수 캡처를 컴파일 에러로 막는다.

    void process() {
    int count = 0;

    class Counter {
        void show() {
            System.out.println(count); // 컴파일 에러 — count가 effectively final이 아님
        }
    }

    count++; // 이 줄 때문에 count가 effectively final이 아니게 됨
}

    익명 클래스 (Anonymous Class)¶

    이름 없이 선언과 동시에 인스턴스를 만든다. 인터페이스나 추상 클래스의 일회성 구현에 쓴다.

    interface Greeting {
    void sayHello();
}

public class Main {
    public static void main(String[] args) {
        Greeting greeting = new Greeting() {
            @Override
            public void sayHello() {
                System.out.println("Hello from anonymous class");
            }
        };
        greeting.sayHello();
    }
}

    effectively final 제약은 지역 클래스와 동일하다. 내부 구조도 지역 클래스와 같이 캡처를 값 복사로 처리한다.

    람다가 가능한 자리(함수형 인터페이스 구현)에서는 람다를 쓰는 게 낫다. 익명 클래스는 다중 메서드를 가진 인터페이스나 상태(필드)가 필요한 경우에 쓴다.

    섀도잉 (Shadowing)¶

    내부 클래스에서 외부 클래스와 같은 이름의 변수를 선언하면 외부 변수가 가려진다.

    public class ShadowingMain {

    public int value = 1;

    class Inner {
        public int value = 2;

        void go() {
            int value = 3;
            System.out.println("value = " + value);                          // 3 (지역 변수)
            System.out.println("this.value = " + this.value);                // 2 (Inner 필드)
            System.out.println("ShadowingMain.this.value = " + ShadowingMain.this.value); // 1 (외부 필드)
        }
    }

    public static void main(String[] args) {
        ShadowingMain main = new ShadowingMain();
        Inner inner = main.new Inner();
        inner.go();
    }
}

    외부 클래스 인스턴스는 외부클래스명.this로 참조한다.

    유형 선택 기준¶

    정적 중첩 클래스를 기본으로 선택한다. 외부 인스턴스 참조가 필요한지 먼저 따진다. 참조가 없는데 내부 클래스를 쓰면 this$0 때문에 외부 인스턴스가 불필요하게 오래 산다.

    조건 선택
    외부 인스턴스를 참조하지 않는다 정적 중첩 클래스
    외부 인스턴스 상태를 자주 읽거나 쓴다 멤버 내부 클래스
    특정 메서드 안에서만 쓰고 재사용 없다 지역 클래스
    한 번만 구현할 인터페이스·추상 클래스 익명 클래스 (또는 람다)
    외부에서 여러 클래스가 사용한다 별도 최상위 클래스

    멤버 내부 클래스를 쓰기로 했다면 인스턴스가 어디까지 퍼지는지 확인한다. 다른 스레드로 전달되거나 컬렉션에 저장되면 외부 인스턴스 수명도 그만큼 늘어난다.

    중첩 클래스를 쓰는 이유¶

    외부 클래스와 한 쌍으로만 쓰이는 클래스를 안에 넣으면 패키지 공개 범위를 좁힐 수 있다. private으로 선언한 중첩 클래스는 외부에서 아예 보이지 않는다.

    외부 클래스의 private 멤버에 직접 접근할 수 있어 불필요한 public getter를 만들지 않아도 된다. Builder 패턴에서 Builder 클래스를 정적 중첩으로 선언하는 것이 대표적인 사례다.

    class Person {
    private final String name;
    private final int age;

    private Person(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
    }

    static class Builder {
        private String name;
        private int age;

        Builder name(String name) { this.name = name; return this; }
        Builder age(int age)      { this.age = age;   return this; }
        Person build()            { return new Person(this); }
    }
}

// 사용
Person person = new Person.Builder()
    .name("홍길동")
    .age(30)
    .build();

    Builder는 Person 인스턴스를 참조할 필요가 없으니 static이다.
